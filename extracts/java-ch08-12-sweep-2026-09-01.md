## ch08 — contentReference

Three different behaviors depending on which walk path meets the referencing element:

| Path | Lines | Reference | Type | Children |
|---|---|---|---|---|
| one-match step-in (diff has child rows, base has none) | PPP:858-896 → `replaceFromContentReference` PU:1870-1874 | **nulled** | **replaced by target's types** | walk target's subtree as base (redirector stack), children = target children merged with diff rows |
| empty-match step-in (no diff row on the element, inner diff rows exist) | PPP:1118-1156 → PU:1870 | nulled | replaced | same |
| sliced-base default, after the new-slice loop | PPP:1477-1479 | **kept** | **cleared** | `outcome` is declared at PPP:1241 as the entry copy and reassigned per new slice (PPP:1385), so after the loop it is the **last-emitted element** (the last new slice, or the entry when no new slices) — only that one element gets `type` cleared while keeping the reference; a typed new slice *had* stepped in via PPP:1422-1469 before the clear (which is why `section:sliceA` has children) |
| slicing-entry inline dump (diff slices a contentReference element, entry has **no** inner diff rows, base has no children) | PPP:402-419 (`else` of `hasInnerDiffMatches` at PPP:377) | kept on the entry | (empty) | target's children **copied inline** under the entry from the base snapshot (`resolveContentReference` PPP:459-473 walks *backwards* to the nearest same-path non-slice element), ids nulled, paths rewritten by `fixForRedirect` (string `replace` of the target path prefix), `updateFromBase` per row — fires precisely when there are no diff rows for the entry's children |

- Target resolution (`getElementById`, PU:3524-3541): `#id` → the element with that **id** in the list being
  walked (`cursors.base`, i.e. the base snapshot — a *profile* when the base is a profile); `url#id` with a
  url ≠ the source SD → `findProfile(url)` and that SD's snapshot. Target not found → throw
  `Unable_to_resolve_reference_to_`. Because `setIds` absolutizes every local reference at the end of each
  generation (below), a profile-on-profile chain carries absolute core urls, so Java (like .NET's
  `getCoreType`) ends up dereferencing into the **core** definition; only a base whose references are still
  local (a hand-written base) resolves within the base itself. → R5 §5.1.0.10 propagation (constraints on
  `Questionnaire.item` flowing into `item.item`) is **not implemented in either engine**; both expand the
  referencing element from the core target and merge only the diff rows under it.
- eld-5 value-domain properties: `replaceFromContentReference` copies **only `type`** — no
  fixed/pattern/binding/defaultValue/example/min-maxValue/maxLength from the target (OQ-004: Java = .NET,
  agreement by omission).
- **Absolutization = `generateIdForElement`** (PU:4359-4363): any `#`-local contentReference is prefixed with
  `getUrlForSource(type, srcSD)` = the SD url for LOGICAL kinds, else `http://hl7.org/fhir/StructureDefinition/<type>`
  (PU:4367-4373). Runs from `setIds(derived, false)` (PU:886) over the whole snapshot **and the caller's
  original differential** (PU:4257-4265 with `checkFirst=false`). = DEV-023 flavor 1 (global, vs .NET's
  merged-children-only `ensureAbsoluteContentReferences`). Note the hard-coded core base url: a constraint
  profile on a *non-core* specialization (custom resource) gets `http://hl7.org/fhir/StructureDefinition/<type>#…`
  regardless of where the type actually lives — wrong target for custom resources (JI-20 candidate,
  needs-verification: does the R6 custom-resource path (§5.4.6.6) hit this?).
- DEV-023 flavor 2 (Java keeps the reference on child-expanded slices) = PPP:1477-1479, the sliced-base
  path (last-emitted element only, see table); the step-in paths do the .NET thing (null + type restore).
  Java is internally inconsistent, and the 1477 quirk means sibling new slices can differ from each other.
- DEV-025 flavor 1 (comp-deep/t21: Java re-expands sliced contentReference entries) = the inline dump
  PPP:402-419: when the diff slices a contentReference element and the entry has **no** inner diff rows on a
  base without children, the target's children are materialized under the entry from the base snapshot;
  slices then get theirs via the one-match path.
- Utilities outside the walk: `getChildMap` (PU:513-560) resolves `#id` / `url#id` for renderers/validators
  (throws "unable to process contentReference" on failure); sort's `find()` follows references with
  `MAX_RECURSION_LIMIT = 10` (PU:387, 3786-3787, ch2 sort — not a generation guard).

## ch09 — logical models & interfaces

- `type` and `derivation` mandatory on every SD (PU:750-758); no parse-from-diff repair (ch3). `type` may be
  an absolute url; `getTypeName()` yields the tail for LOGICAL kinds (StructureDefinition.java:5347-5350) and
  drives both `checkDifferential` and the specialization rebase (`cloneSnapshot`, ch3 correction).
- Root `type` allowed only for LOGICAL (PU:882-883 snapshot side `throw new Error`; PU:1318-1323 differential
  side, with the opt-in `wantFixDifferentialFirstElementType` clear when the type equals the base's).
- Logical-typed children pass the step-in gate at PPP:828 through `isBaseResource` (= "types non-empty and
  none is `Resource`", PU:1700-1709), not `isDataType` (which requires COMPLEXTYPE+SPECIALIZATION,
  PU:3590-3597). Type SD resolution for an absolute-url code: `getProfileForDataType` →
  `fetchTypeDefinition(workingCode)`; `isMatchingType`'s `tsd.getUrl().equals(tr.getCode())` branch
  (PU:1650) is the logical-model case.
- **Specialization append** (PU:842-867): diff rows the walk did not consume (`SNAPSHOT_GENERATED_IN_SNAPSHOT`
  unset) and not root: if an element with that path exists in the current context → merged onto it
  (`updateFromDefinition`), else `updateURLs`-copied and **inserted after the last child of its parent**
  (`findLastChildForParent`, throws "internal code error" if the parent path is absent); if the row "walks
  into" children (next diff row is a child): >1 type → throw "Unsupported scenario: specialization walks
  into multiple types", else `addInheritedElementsForSpecialization` (PU:1263-1283) copies the type's
  snapshot children under it (path `replace(typeName, path)` — plain string replace), appends the type root's
  constraints and adds its non-`NON_INHERITED` extensions if absent. = Java's "anonymous/new element" story
  for specializations and logical models; .NET = `createNewElement` + inline children (ch7/ch9). Neither
  side synthesizes definition/min/max (sdf-3): PU:969-975 only fills a missing `base` from the element's own
  path/min/max.
- **Choice-group pruning** (`checkGroupConstraints`, PU:1333-1405, called at PU:841 right after the walk):
  for every non-sliced, non-prohibited snapshot element, each `constraint` whose FHIRPath expression parses as
  a parenthesised union of child names compared to the constant `1` (`= 1` → mandatory group, `<= 1` →
  optional group; `readChoices`/`processConstraint` PU:4820-4870) defines a choice group over the element's
  direct non-slice children. If exactly one group member has `min = 1`, every **other** member is set
  `max = "0"` (the member row itself stays) and all its **descendants are removed** from the snapshot
  (`addAllChildren`); two mandatory members → `throw new
  Error("Error: there are two mandatory elements …")`; duplicate child names → `throw new Error("huh?")`.
  Java-only surface (xml-choice-group / logical-model idiom); .NET has nothing comparable. Rows removed
  here still count as "generated" for the orphan check (their diff rows were matched before removal).
- **Interfaces**: no `structuredefinition-interface` handling in PU/PPP/PRE, nor in
  `org.hl7.fhir.r5/context/` or elsewhere under `conformance/` (git grep, only `ExtensionDefinitions`
  defines the constant). `checkTypeDerivation` PU:3276 treats **abstract or LOGICAL** base types as
  walkable ancestors for type-derivation checks — the closest thing to interface awareness.
  imposeProfile: only `sdConformsToTargets` PU:3333 (targetProfile derivation may pass through an imposed
  profile); PRE:607 "we ignore impose and compliesWith - for now?". So `mi-use-imposed` succeeds in Java
  because the imposed profile satisfies the *targetProfile* check, not because anything is merged.
- `populateLogicalSnapshot` (PU:4546-4567): a separate utility (root = diff root copy; base snapshot children
  + diff children re-rooted by string prefix) — no caller in the cone (publisher-side helper for models
  without a generatable base); not part of `generateSnapshot`.
- Type parameters (`checkTypeParameters`, PU:1159-1180, ch3) — Java-only.
- DEV-031 (cdshooks `prefetch` segment dropped by .NET): Java's path handling for logical-model children is
  the ordinary `fixedPathDest` remap (PU:2051-2071) — nothing logical-specific; the .NET bug remains
  untraced on the .NET side.

## ch10 — ids & Base

- `setIds(sd, checkFirst)` (PU:4256-4267): with `checkFirst=false` (the generator's own call, PU:886)
  regenerates ids on **both** the differential (the caller's original — the clone `diff` is a separate list)
  and the snapshot; with `checkFirst=true` only when some element lacks an id (the driver's pre-call,
  driver:548/600, passes `false` too).
- `generateIds` (PU:4310-4364): per element, id = path segments joined by `.`, each non-root segment
  `fixChars(segment)` (`_` → `-`, PU:4375-4377; no shared test has an underscore path — no exhibit) plus
  `:sliceName` for every prefix that is currently a named slice (`SliceList`: the nearest enclosing slice
  per path prefix, cleared when a shallower-or-equal path appears; reslice `/` is inside the name). **No
  `[x]` normalization from `Base.path`** — the walk already emitted normalized `[x]` paths (`fixedPathDest`;
  renamed diff paths collapsed at PPP:830-842), so ids never depend on `Base` (.NET's do, ch10). Existing
  ids are overwritten unconditionally (author ids discarded → OQ-009 Java = agreement with .NET); an
  `replacedIds` map is filled but the "second pass — fix up any broken path based id references" is an empty
  comment (PU:4322-4323) — dead bookkeeping. Duplicate generated id → ERROR `SAME_ID_ON_MULTIPLE_ELEMENTS__IN_`
  (message, not throw). Element without path → throw `NO_PATH_ON_ELEMENT_DEFINITION__IN_`.
- Base component: `updateFromBase` (PU:2004-2020, J-a): copy the base row's `base` verbatim if present, else
  seed from the base row's own path/min/max; applied to every emitted row (incl. type-snapshot rows during
  step-ins → the type's Base, like .NET's `copyChildren`); specialization rows still lacking one get a
  self-referential Base (PU:969-975); user data `SNAPSHOT_BASE_MODEL` (source SD url) + `SNAPSHOT_BASE_PATH`
  record provenance per row. Root: Java does not special-case the root (its base is whatever the base
  snapshot's root Base says — for a core resource that is `Resource`-derived, e.g. `Patient` root Base =
  `Patient`? — the core snapshot supplies it; .NET forces root Base = self).

## ch11 — recursion

- Guard: `snapshotStack` (PU:436, instance list of **derived urls**) checked/pushed at PU:774-778 per
  `generateSnapshot`, popped in `finally` (PU:1089); plus the SD-level flag `setGeneratingSnapshot(true)`
  (PU:777, cleared 1083/1088) read by `checkNotGenerating` (PU:1694-1698, `FHIRException`
  `Attempt_to_use_a_snapshot_on_profile__as__before_it_is_generated`) and by PPP:714/719/744.
- Re-entry sites (all synchronous, same instance): PU:767 (base of a snapshot-less base), PU:2080
  (`getProfileForDataType` xver), PU:2638 (doc-override xver), PPP:710 (template xver), PPP:730 (snapshot-less
  type profile). Any exception → `derived.setSnapshot(null)` (PU:1078-1084): no half-built snapshot escapes.
- In-progress profile as a type profile (PPP:714-724): type-compat check skipped, only the already-built
  **first element** is used (empty → throw). This is what lets `ext-recursion-2` (slice typed with its own
  url) generate: the self-reference is met while the SD is mid-generation, the root is already there, the
  slice has no diff children so no step-in. `logical-goo`: the caller hands `generateSnapshot` a base
  *object* with a snapshot; the stack only holds the derived url, and the base is never re-entered.
  `ext-recursion-1` (self-type on the root): rejected structurally by `checkDifferentialBaseType`
  (PU:1322) before any recursion (DEV-029 mechanisms pinned).
- Terminator: diff-driven step-in (children expanded only where the diff has child rows — PPP:828-829,
  1077, 1422-1424, 1658) — same policy as .NET — **plus** the contentReference inline dump (PPP:402-419),
  which materializes one extra level precisely when the sliced entry has no diff child rows (DEV-025
  flavor 1).
- No root-only re-entry channel and no caching of roots (.NET `CACHE_ROOT_ELEMDEF`); no cycle guard on the
  `findProfile` base-chain walks in `isMatchingType`/`isCompatibleType`/`checkTypeParameters`/
  `checkTypeDerivation` (PU:1665, 1477, 1175, 3280) — a cyclic `baseDefinition` chain loops forever there
  (cf. .NET's unguarded `getSnapshotRootElement` step 4).
- Statefulness: `snapshotStack`, `messages`, `obligationProfiles`, `childMapCache`, `xver`, `defWebRoot`
  are instance state; `setGeneratingSnapshot` is on the shared SD object (visible to every
  `ProfileUtilities` instance using the same context). Not thread-safe; no overlapping-call detection.
